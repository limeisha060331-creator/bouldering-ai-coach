# AI 成本模型

> 由 `npm run cost:report` 生成。价格或假设变化后重跑，不要手改数字。

## 1. 口径

- 币种：美元挂牌价，按固定汇率折算人民币。
- 汇率假设：1 USD = 7.1 CNY（2026-10-25）。
- 成本是预算估算，不是 provider 账单。真实成本以 API 返回的 usage 为准。
- 视频按 Gemini 官方 263 tokens/秒估算；抽帧按每帧 258 tokens 估算。

## 3. Token 假设

- Gemini 视频：263 tokens/秒。
- Gemini 音频：32 tokens/秒。
- 抽帧：桌面端默认 16 帧，每帧按 258 tokens 估算。
- 中文文本：1.6 字符/token；英文：4 字符/token。

## 7. 解读

- 常规 45 秒片段：Gemini 直传 $0.0064/次，DeepSeek 抽 16 帧 $0.0013/次，后者约为前者的 1/4.8。
- 抽帧更便宜，但丢失帧间连续动作，时间轴点评的连续性会下降。成本差异必须用质量差异来换。
- 在当前单价下，模型调用不是主要成本；视频存储、带宽、失败重试和人工支持更值得盯。

## 8. 真实调用校准

来源：`evals/runs/live-baseline-2026-10-26`，10 条真实视频，Gemini 直传，成本取自 provider 返回的 usageMetadata。

| 项 | 估算 | 实测 | 估算偏差（正数=高估） |
| --- | ---: | ---: | ---: |
| 单条成本 | $0.0065 | $0.0071 | -9.2% |
| 单条输入 tokens | 11,058 | 11,996 | -7.8% |
| 单条输出 tokens | 1,256 | 1,406 | -10.7% |

端到端耗时：平均 51.9s，其中上传 20.2s，生成 25.1s。

- 估算偏差主要来自输出长度：同一条 46 秒视频两次运行分别产出 16 段和 29 段，输出 token 相差近一倍，这部分模型不保证。
- 因此月度预算要在这个实测值上留 10% 余量，而不是直接用理论估算值。

## 9. 更新方法

1. 改 `lib/ai-cost.ts` 里的 `MODEL_PRICING` 或 `TOKEN_ASSUMPTIONS`。
2. 跑 `npm run cost:report` 重新生成本文档。
3. 每次跑完 `eval:live` 后重跑本脚本，第 8 节会自动换成最新一次真实调用。
