## D-001 先建评测与成本基线，暂不微调

- 日期：2026-10-26
- 类型：策略
- 状态：已采纳
- 假设：当前最大的问题不是模型能力，而是没有稳定的质量口径和成本口径；没有评测就做微调，无法判断是否变好。
- 改动：新增 `evals/` 评测链路、`lib/ai-cost.ts` 成本模型、失败分类与决策规则。
- 主指标：格式合法率、时间戳可定位率、维度分覆盖率。
- 护栏指标：单次成本、P0 失败数。
- 样本：3 条合成夹具，仅用于验证链路。
- 决策规则：先让评测可复现，再谈模型优化；合成夹具不参与上线决策。
- 结论：链路跑通。基线 65.5 分、3 个 P0；候选 96.2 分、0 个 P0；成本 +6.7%。由于是合成数据，这次结论只确认工具可用。
- 回看条件：拿到 20 条真实视频和双人标注后，重跑基线，再决定是否进入结构化输出 v2。

## D-002 下一候选：结构化输出 v2 + 证据链

- 日期：2026-10-26
- 类型：实验
- 状态：提议
- 假设：把自由文本换成带 `timestamp / evidence / confidence / dimensionScores` 的 schema，可以同时提升格式合法率、时间戳可定位率和维度分覆盖率。
- 改动：Prompt 与解析器改为 schema 主路径；正则只做旧数据兼容；UI 展示证据帧与置信度。
- 主指标：综合质量分、维度分覆盖率、维度分 MAE。
- 护栏指标：格式合法率 ≥ 98%、时间戳可定位率 ≥ 95%、单次成本涨幅 ≤ 20%、P0 失败不增加。
- 样本：20 条真实视频，其中 8 条双人标注。
- 决策规则：质量分提升 ≥ 2pt 且无红线则上线；任一红线跌破则回滚；提升不足则继续迭代。
- 结论：待跑。
- 回看条件：首轮 20 条跑完，且人工复核至少 5 条低置信度点评。

## D-003 保留 Gemini 直传与 DeepSeek 抽帧双后端

- 日期：2026-10-26
- 类型：策略
- 状态：已采纳
- 假设：国内网络与成本约束下，单一后端无法同时满足“连续动作理解”和“低单价”两个目标。
- 改动：网页端保留 Gemini 视频直传；桌面端默认本地抽 16 帧走 DeepSeek，可切换 Gemini。
- 主指标：单次成本、时间戳连续性、用户可选性。
- 护栏指标：不因抽帧引入时间戳越界；切换后端不改变报告结构。
- 样本：成本模型按 15/45/90 秒三档估算。
- 决策规则：成本差异必须用质量差异解释，不能只按单价选型。
- 结论：45 秒常规片段，Gemini 约 $0.0064/次，DeepSeek 约 $0.0013/次，后者约为前者的 1/4.8；抽帧丢帧间动作，保留双后端。
- 回看条件：接入姿态关键点或帧插值后，重新评估抽帧方案的质量差距。

## D-004 暂不做微调

- 日期：2026-10-26
- 类型：策略
- 状态：已采纳
- 假设：当前没有足够的“采纳/拒绝”标签，微调无法验证收益，反而会增加维护成本。
- 改动：不投入 SFT/DPO；先把用户反馈收集进评测集。
- 主指标：反馈标签数量、badcase 回流率。
- 护栏指标：不因微调引入新的 P0 失败。
- 样本：目标 200 条带原因码的反馈。
- 决策规则：只有当同类失败在评测集里稳定复现、且 Prompt/RAG 已经无法改善时，才考虑微调。
- 结论：暂缓。
- 回看条件：累计 200 条反馈，且 top 3 失败类型的占比超过 50%。
