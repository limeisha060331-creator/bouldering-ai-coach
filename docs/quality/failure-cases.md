# 失败案例库

这份清单只记录能从代码或报告里复现的失败，不写“模型有时不太稳定”这种无法回归的描述。

## F-01 自由文本解析脆弱

**现象**：模型偶尔用 `00:12 -`、`12秒` 或中文引号组织点评，正则匹配不到，整条点评丢失。

**证据**：`lib/analyze-prompt.ts` 要求模型“禁止使用任何双引号”，本质是用 Prompt 迁就 `lib/parse-analysis.ts` 的正则。`evals` 的 malformed 夹具能复现时间戳解析问题。

**影响**：报告缺段、时间轴不完整，用户以为模型没看出来。

**当前处理**：正则兜底 + 空正文错误。

**下一步**：结构化输出为主路径，正则只做旧数据兼容；解析失败返回明确错误，不静默丢段。

**回归**：`evals/fixtures/case-003-malformed.json`，检查 `NO_TIMESTAMPED_SEGMENTS` 与 `TIMESTAMP_OUT_OF_RANGE`。

## F-02 时间戳越界或倒序

**现象**：模型给出 `[01:12]`，但视频只有 60 秒；或者先写 `[00:30]` 再写 `[00:12]`。

**证据**：当前解析只把 `MM:SS` 转成秒数，没有拿视频时长做校验，也没有排序。合成夹具 case-003 复现了两种问题。

**影响**：用户点时间轴跳不到对应画面，直接破坏“可回看”的核心承诺。

**当前处理**：评测报告标记 `TIMESTAMP_OUT_OF_RANGE` 和 `TIMESTAMP_NOT_MONOTONIC`。

**下一步**：解析后校验 `0 <= t <= duration + 2s`；越界条目丢弃或标记为不可定位；按秒数稳定排序。

**回归**：case-003，两个失败码都必须出现。

## F-03 正确但不可执行

**现象**：“注意重心”“多练习”“加强核心”这类点评，听起来没错，但用户不知道下一次具体改什么。

**证据**：`GENERIC_ADVICE` 指标；case-002 的 4 条点评全部命中空话短语。

**影响**：用户看完仍不知道怎么练，复购和口碑都受损。

**当前处理**：空话率进入评测，超过 30% 记 P1。

**下一步**：Prompt 禁用句式；每条点评必须包含“看到了什么 + 为什么错 + 下一次怎么做”；把动作库检索结果作为处方依据。

**回归**：case-002，`genericAdviceRate > 0.3` 且出现 `GENERIC_ADVICE`。

## F-04 难度判断偏差

**现象**：用户标注 V5，模型判断 V3，且没有置信度。

**证据**：Prompt 里难度是可选行，输出只有 `难度：Vx`；case-003 复现了 V3 对 V5。

**影响**：评分脱离难度语境，用户会觉得“它根本不懂这条线”。

**当前处理**：`GRADE_MISMATCH` 进入评测；难度一致率只观察，不设硬门槛。

**下一步**：把用户填写的难度作为上下文传入；模型只做区间修正；允许输出“无法判定”；按难度分档校准。

**回归**：case-003，`gradeMatch === false` 且出现 `GRADE_MISMATCH`。

## F-05 模型返回空正文

**现象**：DeepSeek 返回空字符串或只有拒答，报告页无内容。

**证据**：`lib/deepseek-analysis.ts` 的 `DeepSeekEmptyAnalysisError`；`lib/process-analysis-job.ts` 对空响应做冷却重试。

**影响**：用户等了很久拿到空白页，属于 P0。

**当前处理**：空响应不计费为成功；后台重试；仍失败则提示换短片段。

**下一步**：补一个 empty-output 夹具，确保回归时能复现并验证错误提示。

**回归**：待补 `evals/fixtures/empty-output.json`。

## F-06 429 / 服务过载

**现象**：DeepSeek 触发限流（429）或返回 5xx，分析中断。

**证据**：`lib/deepseek-analysis.ts` 的 `describeDeepSeekStatus` 区分可重试与不可重试；`lib/process-analysis-job.ts` 用 `retryAfter` 驱动 `rate_limited` 状态。

**影响**：用户看到长时间等待或失败，容易重复点击，进一步加剧限流。

**当前处理**：冷却倒计时、自动重试；402 余额不足与 401 Key 失效直接给可操作文案。

**下一步**：加用户级配额与队列；把失败原因分布接进看板。

**回归**：`tests/deepseek-analysis.test.ts` 覆盖 429 重试与 402 不重试。

## F-07 视频过长 / 帧过大

**现象**：视频超过 10 分钟，或关键帧总大小超过 3.2MB，请求被拒。

**证据**：`lib/analyze-request.ts` 的 `MAX_DURATION_SEC` / `MAX_TOTAL_DATA_URL_CHARS`；前端抽帧默认 16 张、单帧 768px。

**影响**：首次上传失败，用户流失。

**当前处理**：抽帧后先校验时长，不提交无效请求；错误文案提示剪辑到 10 分钟以内。

**下一步**：上传前预检时长、清晰度和人物完整度；把废片率做成产品指标。

**回归**：上传超限用例，返回 413 且文案可执行。

## F-08 视频 Blob 不清理

**现象**：分析完成后，上传到 Vercel Blob 的视频和 job JSON 仍保留。

**证据**：`lib/analysis-jobs.ts` 只有 `put` 和 `get`，没有删除逻辑；`lib/process-analysis-job.ts` 完成后不清理。

**影响**：隐私风险和存储成本随时间累积。这不是模型失败，但会出现在尽调或安全评审里。

**当前处理**：私有 Blob，浏览器不直连。

**下一步**：分析完成即删视频；job 记录设 TTL；提供“本地优先”模式说明。

**回归**：任务完成后检查 Blob 列表为空。

## F-09 输出契约缺失：没有总分，也没有 5 维分

**现象**：10 条真实抱石视频，10 条都没有「评分：xx/100」这一行，也没有「维度分：…」这一行。

**证据**：`lib/analyze-prompt.ts` 全文只要求了一个结构化字段——`难度：V数字`。用 `rg -n "评分|维度分" lib/analyze-prompt.ts` 只能命中难度那一行。真实基线报告里 `SCORE_MISSING` 与 `DIMENSION_SCORES_MISSING` 都是 10/10，而同一批输出的可解析率和时间戳可定位率都是 100%。

**影响**：这是 P0。UI 和评测都按「有总分」消费输出，拿不到分数就没法做版本间可比，也无法把点评折算成一个可解释的等级。注意根因不是模型能力：模型把时间戳和动作描述都写对了，是 Prompt 从来没要求总分。

**当前处理**：评测把缺失记成 P0，不静默降级成「无分数但算通过」。

**下一步**：结构化输出 v2 把 `score`、`dimensionScores` 纳入 schema 必填；`score` 由 5 维分加权生成并标注来源是「模型给分」还是「加权计算」，不允许两处同时给且互相矛盾。v2 代码已落地（`lib/analysis-schema.ts`），默认关闭，待真机对比（见 D-006）。

**回归**：`npm run eval:live -- --only gym-rockspot-v3`，要求契约完整率从 0% 变 100%。

## F-10 难度判断向中间回归

**现象**：模型给出的难度只落在 V5–V7 这一小段，无论视频实际是 V3 还是 V11。

**证据**：真实基线上 4 条有外部可核对难度的样本，只对 1 条：V3→V3（对）、V6→V5、V10→V6、V11→V6。另外 6 条赛事视频没有公开难度，模型也统一给了 V5–V7。

**影响**：难度是点评的语境。把 V10 说成 V6，等于告诉用户这条线很简单、只是你没做好，高水平用户会直接失去信任；反过来把 V3 说成 V6 又会打击新手。

**当前处理**：难度一致率只观察、不设硬门槛，避免用一个不可靠指标否掉整版。

**下一步**：把用户填写的难度作为输入上下文传入；模型只允许在给定难度上下做一个区间的修正；允许输出「无法判定」；按难度分档统计偏差，而不是只看总体一致率。

**回归**：`npm run eval:live -- --only hueco-fern-roof-v10,hueco-schwerer-gustav-v11`，检查是否仍然把两条完全不同的线判成同一个等级。

## 失败级别定义

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| P0 | 报告不可用或误导用户，例如空正文、无总分、时间戳越界 | 发布前清零或书面豁免 |
| P1 | 报告可用但质量明显下降，例如空话、漏关键动作、维度分缺失 | 进入下一迭代，连续两版不改善则升级 |
| P2 | 体验瑕疵，例如难度未判定、单条过短 | 排入常规优化 |
