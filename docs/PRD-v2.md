# 产品需求文档（PRD）

**项目名称：抱石 AI 动作分析应用（对标 Cruxie 的下一版本）**

---

## 1. 需求背景

### 市场背景

室内抱石馆在国内快速铺开，把抱石当技术运动来练的爱好者越来越多。目前岩馆的指导主要依赖现场教练，一次点评只能覆盖当次攀爬，而且必须教练恰好在场。市面上已有的回放工具只能让用户看到自己掉了，看不出问题出在哪一步。通用大模型虽然能聊攀岩，但不提供带时间戳的逐段点评、训练记录和可导出的报告。

与此同时，海外同类产品已经出现。Cruxie 用 3D 姿态估计给攀岩视频打百分制评分，并自动定位分数下滑最狠的一段，把「感觉不对」变成了「数字不对」。它证明了用户愿意为客观的动作反馈付费，也暴露了三个空白：分数没有解释为什么、结论没有落到下一次训练、评分缺少难度语境。我们的目标是推出一版面向抱石爱好者的 AI 动作分析应用，把一段攀爬视频变成可回看、可积累、可执行的技术反馈。

### 产品目标

- 上传一段抱石视频，自动生成带 `[MM:SS]` 时间戳的逐段点评。
- 输出评分、难度（V 级）判断与专项改进建议，并让每个扣分点都能对应到一句可执行的动作口令。
- 沉淀训练历史，按天汇总爬升距离与最高 V 级，形成进步曲线。
- 提供维度雷达图，支持与上一次或上一个月叠加对比。
- 收藏关键片段，随时跳回原视频对应的秒数反复对照。
- 支持单次分析的 PDF 与 Markdown 报告导出，并生成可分享的分享卡。
- 保证国内网络下稳定可用，同时提供网页端与桌面端两种形态。

### 目标用户

- 目标用户群体：18 至 40 岁、每周进岩馆两三次、把抱石当技术运动来练的爱好者，水平大致在 V2 到 V6。
- 用户画像：没有固定教练的自学者、想靠录像复盘的进阶玩家，以及需要给学员出书面结论的岩馆教练（次要用户）。
- 用户痛点：动作质量只有旁观者看得见、点评估赖教练是否在场、通用工具给不出可回看可积累的结构化结果、训练进步缺少可量化的记录。

## 2. 功能描述

### 功能概述

应用主要功能包括拍摄引导与上传预检、AI 动作分析、归因翻译层、结果查看、维度雷达对比、训练历史、片段收藏、进步统计、报告导出与分享卡、训练闭环建议，以及多模型与多形态支持。用户选择一段抱石视频并填写难度与攀爬情况，即可得到带时间戳的逐段点评与可执行的改进方向；分析记录保存在本地，登录后可同步到云端。

### 功能详细描述

**· 拍摄引导与上传**

- 功能点 1：在录制与选择视频之前给出拍摄框、稳定性与时长提示，明确要求全身与整面岩壁入镜，并在手机晃动或人物出画时给出实时提醒。
- 功能点 2：上传前对素材做一次可解析性预检，判断视频长度、画面清晰度与人物完整度；不合格时在提交之前拦下，并给出具体重拍建议，不提交无效请求。
- 功能点 3：支持选择本地视频，在浏览器端压缩到 3.5MB 以内后上传，压缩失败时给出明确提示。
- 功能点 4：分析开始前可填写难度（V 级）、本次攀爬结果与训练备注，作为后续评分语境与统计的数据来源。

**· AI 动作分析**

- 功能点 5：调用多模态模型分析视频，输出格式固定为每行 `[MM:SS]` 时间戳加一句点评，覆盖起步、重心转移、脚点使用、发力顺序与完攀动作。
- 功能点 6：支持轻量（light）与深度（deep）两档分析深度，轻量档控制字数与条数，深度档给出完整的生物力学向分析。
- 功能点 7：支持中文与英文两种输出语言，界面语言与分析输出语言相互独立。

**· 归因翻译层**

- 功能点 8：把评分拆解为若干维度，每个维度给出分值，并在分值之下补充一句「身体当时发生了什么」的归因描述。
- 功能点 9：每个扣分维度自动生成一条下一次尝试的动作口令，口令使用具体动作词，不使用「注意重心」这类无法执行的表述。
- 功能点 10：在结果页给出本次分数的档位说明，以及同难度下的参考区间，让用户知道自己的位置。

**· 结果查看**

- 功能点 11：结果页按时间轴展示逐段点评，并给出总分、教练金句、难度判断、维度总结与专项改进建议。
- 功能点 12：给出维度雷达图，并支持与上一次或上一个月的数据叠加，直观看到哪些维度在涨、哪些在退。
- 功能点 13：提供时间轴分数曲线，曲线随视频播放同步移动，可一键跳到分数下滑最明显的位置。
- 功能点 14：每条分析记录标注 Prompt 版本、分析深度与输出语言，便于对比不同版本的结果。

**· 训练历史**

- 功能点 15：分析记录保存在本地数据库（IndexedDB），支持按日期（7 天或 30 天）与分数区间筛选、关键词搜索与删除。
- 功能点 16：历史列表支持按日期与按分数两种排序方式，并自动标出本周最佳的一次。
- 功能点 17：登录后可把记录镜像到云端，换设备登录即可拉回历史。

**· 片段收藏与回看**

- 功能点 18：时间轴上的任一片段可一键收藏，收藏夹中能跳回原视频对应的秒数反复对照。

**· 进步统计**

- 功能点 19：按天汇总爬升距离与最高 V 级，生成训练趋势曲线与累计爬升数据。
- 功能点 20：进步曲线按难度分档解读，避免不同难度的同分被放进同一个标尺。

**· 报告导出**

- 功能点 21：单次分析可导出单页 A4 PDF 报告或 Markdown 全文。
- 功能点 22：可生成一张适合分享的分享卡，包含总分、维度雷达与本次关键结论。

**· 训练闭环**

- 功能点 23：由本次分析的扣分点自动生成下一次的训练目标与专项 drill，形成「本次复盘到下次计划」的闭环。
- 功能点 24：训练目标可在进步页查看完成情况，并与后续分析结果关联。

**· 多模型与使用形态**

- 功能点 25：网页端使用 Gemini 直接理解视频；桌面端默认使用 DeepSeek（本地抽帧），并可在设置中切换到 Gemini。
- 功能点 26：提供中文与英文界面、浅色与深色主题，以及可选的本地账户。

### 优先级

- 必须实现：功能点 1、2、3、4、5、8、9、17、18、25。
- 应该实现：功能点 6、7、10、11、12、15、16、19、21、26。
- 可以实现：功能点 13、14、20、22、23、24。

## 3. 交互流程

### 用户流程图

- 用户打开应用，在首页点击「开始分析」进入分析页。
- 用户在分析页先看到拍摄提示，确认拍摄要求后选择视频，页面即时反馈素材是否合格。
- 素材合格后，用户填写难度、攀爬结果与训练备注，选择分析深度与输出语言。
- 用户点击「开始分析」，页面依次显示本地处理、上传、模型处理、生成报告四段进度，并给出剩余时间预期，中途可随时取消。
- 等待期间用户可以离开页面，任务在后台继续推进，回来时按任务编号恢复进度。
- 分析完成后进入结果页，查看时间轴点评、总分、维度雷达、分数曲线、难度判断与专项改进建议。
- 用户可在时间轴上收藏关键片段，在专家建议中查看本次扣分对应的动作口令，也可导出报告或分享卡。
- 用户在历史记录中筛选与回看以往的分析，在进步页查看训练趋势与本周最佳。

### 界面原型

提供低保真可点击原型，展示首页、分析页、分析中（进度）、结果页、历史记录页与进步页六个核心页面，另附拍摄引导与分享卡的局部状态。原型文件见 `docs/prototype/index.html`。

### 页面跳转

- 首页 → 分析页 → 分析中（进度）→ 结果页。
- 结果页 → 收藏夹 → 跳回原视频对应秒数。
- 结果页 → 报告导出 → 分享卡。
- 分析页 → 历史记录 → 结果页。
- 导航栏 → 进步页或收藏页或设置。

## 4. 数据指标

### 产品 KPI

- 用户增长率：每月新增用户数。
- 活跃度：日活跃用户（DAU）与月活跃用户（MAU）的比值。
- 留存率：7 日留存率与 30 日留存率。
- 转化率：从首次打开到完成首次分析的转化率。
- 二次上传率：7 日内再次上传视频的用户占比。
- 付费转化率：从免费次数用尽到购买套餐的转化率。

### 功能指标

- 分析成功率：90% 以上，指从点击开始分析到产出非空且可解析的报告。
- 分析耗时：端到端 P50 不高于 3 分钟，P90 不高于 8 分钟，进度状态可实时轮询。
- 废片率：因拍摄不合格导致的首次重拍不高于 15%。
- 上传限制：视频压缩到 3.5MB 以内，超限时引导压缩而不是直接报错。
- 报告导出率：不低于 20%。
- 片段收藏使用率：不低于 30%。
- 用户满意度：结果页满意度评分不低于 4.5 分。

### 数据跟踪与分析

- 收集分析成功率、失败原因分布（429 限流、配额耗尽、超时、上传超限、解析失败）、导出率、分享卡生成率与筛选使用频率，通过分析优化用户体验。
- 使用 A/B 测试对比不同 Prompt 版本，按固定评测集评估点评质量与归因准确度。
- 埋点上线 30 天后回看以上指标，作为下一版本功能排序的依据。
- 单独跟踪「分数到动作口令」的点击与采纳率，验证归因翻译层是否真的被使用。

## 5. 技术和资源要求

### 技术架构

- 前端：React 19 加 TypeScript 加 Tailwind CSS 4，网页版基于 Next.js 16 App Router，桌面版基于 Electron 加 Vite。
- 后端：Next.js Route Handlers，使用 RESTful API，视频分析走异步任务与状态轮询。
- AI：Google Gemini（直接理解视频）与 DeepSeek（本地抽帧加图像理解）双后端。
- 存储：浏览器 IndexedDB 本地优先，Vercel Blob 临时托管视频。
- 数据库：Supabase（PostgreSQL），存储账号与云端分析记录。
- 云平台：Vercel，提供部署与服务端运行环境。

### 资源需求

- 开发人员：前端工程师 2 人、后端工程师 1 人。
- 设计人员：1 名 UI 与 UX 设计师。
- 测试人员：1 名 QA。
- 预算：预计开发周期为 4 个月，预算为 30 万元人民币。

### 开发计划

## 7. 风险与应对措施

### 潜在风险

- 技术难题：模型配额与限流导致分析失败，视频体积与时长受上传上限约束。
- 技术难题：不做独立姿态估计，就无法给出像竞品那样的骨骼、受力与重心量化指标，评分可信度会被质疑。
- 市场变化：同类 AI 运动分析产品出现，瓜分用户注意力。
- 用户反馈：AI 点评被认为「说了但没说到点上」，用户对上传自己的攀爬视频有顾虑。

### 应对策略

- 技术应对：浏览器端压缩加异步任务加失败重试，并给出冷却倒计时；失败原因分类展示；需要更高精度时引导切换到直接理解视频的模型。
- 技术应对：先把「分数到动作口令」的翻译层做扎实，用可执行性换取可信度，把姿态估计列为下一阶段的技术预研，不阻塞当前版本。
- 市场应对：聚焦抱石这一垂直场景，与岩馆合作获取种子用户；用难度语境与报告导出建立与竞品的差异。
- 用户反馈：建立固定评测集，按 Prompt 版本做回归与 A/B 对比；要求点评必须定位到具体秒数与具体动作；说明记录默认保存在本地，并提供一键清除。

## 8. 附录

### 术语表

- 抱石：不使用绳索、在低矮岩墙上完成的攀爬形式。
- V 级：抱石难度分级体系，数字越大难度越高。
- 动作分析：依据视频判断重心转移、脚点使用与发力顺序等问题的过程。
- 时间轴点评：按 `[MM:SS]` 时间戳逐段给出的点评。
- 归因翻译层：把扣分维度翻译成身体原因与下一次动作口令的中间层。
