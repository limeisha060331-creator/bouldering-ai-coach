# 竞品分析：Cruxie 逆向拆解

对标对象：cruxie.app（Cruxie — AI Climbing Coach）

| 项目 | 内容 |
| --- | --- |

| 产品主体 | ORESHIHON Inc.（官网版权署名） |

| 维度 | 评分对象 |
| --- | --- |
| Keep 四点保持 | 手、脚与重心是否协同稳定，有没有多余晃动 |
| Smooth 流畅度 | 检测急促动作造成的损耗 |
| Tech 技术运用 | 身体使用方式的多样性 |
| CoG Position 重心位置 | 重心是否落在所抓岩点的正下方 |
| CoG-Drive 重心主导 | 重心是否先于手开始移动 |

## 2. 逆向产品拆解

拆解链路：目标用户 → 核心场景 → 用户路径 → 功能问题 → 优化方案 → 验证指标。

### 2.1 目标用户

**人群（推断）**

- 以室内抱石为主要训练方式的成年爱好者，水平大致落在 V2 到 V6。
- 把抱石当作「技术运动」来练，而不是纯娱乐消遣。
- 存在明显的瓶颈焦虑：卡在某个级别或某条线，长期没有突破。

**画像（推断，依据是产品的设计取向）**

- 量化型自学者：没有固定教练，愿意为客观数字付费。
- 瓶颈焦虑者：一条线磕了很多次，想知道自己到底崩在哪一步。
- 游戏化反馈爱好者：官网直接拿「卡拉 OK 评分」作类比，说明产品假设用户吃这套反馈。
- 多语言用户：同时提供 7 种语言，说明目标是全球市场而非单一地区。

**痛点（事实，对应用户会被产品话术击中的四个点）**

- 动作质量只有旁观者看得见，点评估赖教练是否恰好在场，且只覆盖当次攀爬。
- 已有回放工具只能让用户看到自己掉了，看不出问题出在哪一步。
- 训练进步缺少可量化的记录，长期没有对比基准。
- 朋友点评不客观，缺少一份「诚实」的反馈。

### 2.2 核心场景

| 场景 | 描述 | 频次推断 |
| --- | --- | --- |
| A 磕线复盘 | 同一条线反复失败，需要在岩馆休息间隙立刻知道哪一步崩了 | 最高频 |
| B 完攀复盘 | 完攀之后想确认是动作真的做对了，还是运气好 | 次高频 |
| C 周期复盘 | 每周、每月对齐自己，看是否在进步 | 周/月频 |
| D 训练留档 | 把每次分析留作下次的对比基准 | 伴随 A、B 发生 |

Cruxie 官网对场景 B 有一句很关键的话「Even on send days, see the weakness hiding in your best climb」，说明它主动把场景从「失败复盘」扩展到了「成功复盘」。

### 2.3 用户路径

主路径（依据官网 SEQ.02 与 FAQ 复原）：

拍视频 → 上传 → 排队等待（几分钟到 15 分钟）→ 看总分（百分制）→ 看时间轴分数曲线 → 定位 crux（分数跌得最狠的一段）→ 查看叠加图层（骨骼、受力、下一个抓点、雷达图）→ 回到岩壁按建议再试 → 在历史里与上个月对比。

关键决策点与对应的流失风险：

| 节点 | 用户的判断 | 流失风险 |
| --- | --- | --- |
| 拍 | 全身是否入镜、手机是否够稳 | 拍摄要求只写在 FAQ，废片风险高 |
| 传 | 是否已注册、免费次数是否用尽 | 注册与付费墙的转化点 |
| 等 | 还要等多久 | 岩馆内最难等待，超过预期就会离开 |
| 信 | 这个分数可信吗 | 不可信就不会回来第二次 |
| 用 | 结论能不能直接指导下一次尝试 | 不可执行就不会产生第二次上传 |

### 2.4 功能问题

以下问题按「拆解得出」列出，P 开头编号。

**P1 分数不解释为什么。** 五个维度只给出分值，缺少「扣了什么分 → 身体当时发生了什么 → 下一次改什么」的因果链。用户拿到 61 分却不知道从哪改起。

**P2 等待时长不确定。** 官方口径是几分钟到 15 分钟，跨度很大。App 内如果没有阶段进度与预期管理，用户会误判为卡死。

**P3 上传前零校验。** 拍摄要求（全身入镜、手机稳定、含完整岩壁）只写在 FAQ，录制环节没有实时引导，废片率高。

**P4 评分缺语境。** 不记录路线难度，V3 的 80 分与 V6 的 80 分被放在同一个标尺上，横向比较会失真。

**P5 只有分数趋势，没有训练闭环。** 有周趋势线和雷达图叠加，但没有 drill 推荐、没有下节课的目标，进步归因停在「看」的层面。

**P6 单视频单分析。** 没有多机位、也没有多次尝试的并排对比，用户无法回答「我第 3 次比第 1 次好在哪」。

**P7 单人闭环。** 隐私优先换来的是教练看不到学员数据，岩馆教练这条渠道用不上。

**P8 没有导出。** 结果只能留在 App 内，不能生成报告或分享卡给教练看。

**P9 覆盖窄。** 目前只做室内抱石，难度攀与速度攀都在「考虑中」。

**P10 评分标尺未公开（推断）。** 133 个关键点加物理受力是很硬核的底座，但用户缺少一个可参照的标尺去理解 60 分和 80 分的界线。

### 2.5 优化方案

每一条问题对应一个改法，并落到需求池里的需求编号。

| 问题 | 优化方案 | 对应需求 |
| --- | --- | --- |
| P1 分数不解释为什么 | 每个扣分点绑定一句「身体发生了什么」和一条下一次尝试的口令，形成「分数 → 归因 → 动作」的翻译层 | R-05、R-06 |
| P2 等待时长不确定 | 复用已有的异步 Job 状态机，把四段进度、当前阶段与剩余时间预期明确展示，失败时给出分类原因与冷却倒计时 | R-08 |
| P3 上传前零校验 | 录制前给出拍摄框、稳定性与时长提示，上传前做一次可解析性预检，不合格直接提示重拍 | R-07 |
| P4 评分缺语境 | 让用户在分析前填写难度（V 级），评分与进步曲线按难度分档解读 | R-04、R-11 |
| P5 没有训练闭环 | 由扣分点自动生成下一次的训练目标与专项 drill，形成「本次复盘 → 下次目标」的闭环 | R-12 |
| P6 单视频单分析 | 允许把同一条线的多次尝试挂到同一个项目下，支持并排对比与分数变化 | R-13 |
| P7 单人闭环 | 报告导出与只读分享链接，让学员主动把结果发给教练 | R-10 |
| P8 没有导出 | 单次分析导出单页 A4 PDF 或 Markdown，并生成适合发圈的分享卡 | R-10 |
| P9 覆盖窄 | 先把抱石做透，再按用户需求评估难度攀 | R-14 |
| P10 评分标尺不透明 | 在结果页给出本次分数的档位说明与同难度参考区间 | R-06 |

### 2.6 验证指标

| 类别 | 指标 | 目标 |
| --- | --- | --- |
| 激活 | 首次上传到首次分析成功完成的转化率 | 不低于 70% |
| 核心行为 | 7 日内二次上传率 | 不低于 40% |
| 质量 | 分析成功率（从点击到产出可解析报告） | 不低于 90% |
| 质量 | 废片率（因拍摄不合格导致的首次重拍） | 不高于 15% |
| 效率 | 端到端时长的 P50 与 P90 | P50 不高于 3 分钟，P90 不高于 8 分钟 |
| 留存 | 7 日留存与 30 日留存 | 7 日不低于 25%，30 日不低于 12% |
| 价值感知 | 报告导出率、片段收藏使用率 | 导出不低于 20%，收藏不低于 30% |
| 满意度 | 结果页满意度评分 | 不低于 4.5 分（5 分制） |

## 3. 与 CRUX 的对比

| 维度 | Cruxie | CRUX（当前实现） | 差距判断 |
| --- | --- | --- | --- |
| 核心输出 | 百分制总分 + 5 维分值 + crux 定位 | 带 `[MM:SS]` 的逐段点评 + 评分 + 教练金句 + 维度总结 + 改进方案 | CRUX 的反馈更接近人类教练语言，Cruxie 的反馈更接近量化仪表 |
| 量化底座 | 3D 姿态估计 133 关键点 + 物理受力 + 岩点识别 | 抽帧后交给多模态模型描述，无独立姿态估计 | Cruxie 明显更硬核，这是最大差距 |
| 难度维度 | 不记录 | 记录难度（V 级）并参与统计 | CRUX 占优 |
| 历史与对比 | 按日期、按分数排序，本月与上月雷达图叠加 | 按日期与分数区间筛选、关键词搜索，进步趋势曲线 | 各有侧重，CRUX 缺雷达图叠加 |
| 回看体验 | 视频与图表联动，可跳到 crux 时刻 | 片段收藏可一键跳回原视频对应秒数 | 接近 |
| 报告导出 | 无 | 单页 A4 PDF 与 Markdown | CRUX 占优 |
| 训练闭环 | 无 drill、无下节课目标 | 有专项改进建议，但没有 drills 与目标管理 | 双方都弱，是共同的空白区 |
| 形态 | 移动 App（Android 已上线，iOS 即将推出） | 网页端与 Electron 桌面端 | 面向的场景不同，桌面端在竞品中稀缺 |
| 模型与网络 | 未公开 | DeepSeek（默认，可直连）与 Gemini 双后端 | CRUX 在国内网络下更可用 |
| 隐私 | 明确声明不共享、不用于训练模型 | 本地优先存 IndexedDB，登录后镜像到云端 | 双方都在意隐私，路线不同 |

结论一句话：Cruxie 强在量化底座与移动端的即时反馈，CRUX 强在教练语言的反馈质量、难度语境、报告导出与国内可用性。真正要补的是量化指标与训练闭环。

## 4. 可借鉴清单

值得直接借鉴：

- 时间轴与视频联动、支持一键跳到关键秒数（Cruxie 的 crux 定位本质就是这个）。
- 分数曲线作为「一眼看懂」的主可视化。
- 本月与上月雷达图叠加，把「进步了多少」变成可看图。
- 分数保留一位小数，让「再快一点」的动机可感知。
- 自动选出本周最佳一次，给用户一个不需要自己整理的成就。

应该避开：

- 把分数当作终点。只给分不给动作，用户看完就忘。
- 把拍摄要求藏在 FAQ。必须在录制环节就拦住废片。
- 让用户面对 15 分钟的未知等待而没有预期管理。

留给我们自己做的空白区：

- 分数到 drill 的自动闭环。
- 难度（V 级）作为评分与进步的语境。
- 面向国内网络与桌面端的形态。
