## 1. 背景与问题

### 1.1 背景

抱石训练高度依赖「动作质量」。多数攀岩者只能靠岩馆教练现场点评，或自己反复看手机视频，缺少可随时获得的、带时间戳的专业反馈。

大模型已具备视频理解能力，但直接「聊天框里贴视频」无法形成产品：缺少上传限制处理、长时间任务、结构化报告、历史记录与导出。

### 1.2 要解决的问题

| 用户痛点 | 产品做法 |
|----------|----------|
| 看不清自己哪里做错 | AI 按 `[MM:SS]` 给出时间轴点评 |
| 教练资源贵、不方便 | 上传短视频即可获得教练风格反馈 |
| 分析过程长、容易失败 | 异步 Job + 进度轮询 + 限流重试提示 |
| 记录散落在手机相册 | 本机 IndexedDB 历史 + 可选账户 |

### 1.3 产品一句话

> 上传抱石攀爬短视频，获得带时间戳的 AI 动作分析、改进建议，并支持历史、收藏与 PDF 报告导出。

## 2. 目标与非目标

### 2.1 产品目标（MVP 已达成）

1. **多模态分析**：用户上传视频 → Gemini 视频理解 → 教练报告。  
2. **结构化消费**：时间轴、评分、维度总结、改进要点可在 UI / PDF 中使用。  
3. **可上线工程**：适配 Vercel Serverless 超时与请求体限制。  
4. **基础产品化**：中英 UI、分析深度、昼夜主题、可选注册登录。  
5. **简历可讲清**：有完整 AI 流水线、Prompt 版本、错误分类与解析层。

### 2.2 非目标（当前不做 / 明确不做）

| 非目标 | 说明 |
|--------|------|
| 替代真人教练的现场保护建议 | 页脚免责声明：仅训练参考 |
| 医疗 / 康复诊断 | 不做 |
| 全国稳定低延迟访问 | 当前托管 Vercel 境外；国内访问不作 SLA |
| 分析记录全量上云跨设备 | 当前主要存 IndexedDB；`userId` 仅为扩展预留 |
| 微信小程序 / iOS Android 上架 | 列为后续路线图，非 MVP |
| 搜索引擎大规模获客 | 已有基础 SEO 文件，非核心 KPI |

## 3. 用户与使用场景

### 3.1 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 业余抱石爱好者 | V0–V6 左右，有手机拍视频习惯 | 快速知道「这一挂哪里浪费」 |
| 有训练意识的进阶者 | 会记难度、爬升、想看进步 | 历史、统计、可导出报告 |
| 招聘方 / 面试官（次要） | 评估作者 AI 工程能力 | 能看仓库、录屏、讲清架构 |

### 3.2 核心场景

1. **一次完整分析**  
   打开 `/analyze` → 选难度/爬升/备注 → 选深度与 AI 语言 → 上传视频 → 等待 1～3 分钟 → 跳转结果页 → 浏览时间轴 / 导出 PDF。

2. **回顾历史**  
   首页左侧或分析页历史列表 → 打开某次分析 → 收藏关键时间轴片段。

3. **看进步**  
   `/progress` 查看累计爬升等统计（来自各次填写的爬升高度）。

4. **注册（可选）**  
   `/auth/register` 创建账户；未登录仍可分析（历史在本机）。

## 4. 功能需求

### 4.1 信息架构与路由

| 路径 | 功能 |
|------|------|
| `/` | 品牌首页：累计爬升、历史侧栏、CTA 去分析 |
| `/analyze` | 上传表单、分析中进度、历史筛选列表 |
| `/analysis/[id]` | 单次分析结果：时间轴、总结、全文、导出、收藏 |
| `/progress` | 进步 / 爬升相关统计 |
| `/favorites` | 已收藏的时间轴片段 |
| `/auth/register` · `/auth/login` | 邮箱注册登录（需 Postgres + AUTH_SECRET） |

### 4.2 功能清单（P0 / P1 / P2）

#### P0 · 必须有（已实现）

| ID | 需求 | 验收标准 |
|----|------|----------|
| F-01 | 视频上传（点击 / 拖拽） | 支持常见视频格式；非法类型有错误提示 |
| F-02 | 客户端压缩 | 过大视频可压缩至约 ≤3.5MB 再上传；失败有提示 |
| F-03 | 分析参数 | 可设难度 V0–V10、爬升高度(m)、备注 |
| F-04 | 分析深度 | `light` / `deep`，影响 Prompt 与 max tokens |
| F-05 | AI 输出语言 | 中文 / English，与界面语言可独立 |
| F-06 | 异步分析 | 生产环境走 Blob Job + 状态轮询；可取消 |
| F-07 | 进度反馈 | 四阶段：本地处理 → 上传 → Gemini 处理 → 生成分析 |
| F-08 | 结果结构化 | 解析出时间轴 segments；尽量解析评分/难度 |
| F-09 | 结果页 | 可浏览总结、时间轴、全文；可收藏片段 |
| F-10 | 本地历史 | IndexedDB 存记录与视频；可筛选日期/分数/关键词 |
| F-11 | PDF 导出 | 单页 A4 风格报告；不因 oklab 颜色崩溃 |
| F-12 | 限流体验 | 429 时显示冷却秒数或可理解错误，支持重试 |

## 5. AI 产品需求（重点）

### 5.1 模型与输入输出

| 项 | 规格 |
|----|------|
| 默认模型 | `gemini-2.5-flash`（可用 `GEMINI_MODEL` 覆盖） |
| 输入 | 压缩后视频 + Prompt（深度 × 语言） |
| 期望输出形态 | 教练叙述体；时间戳行严格 `[MM:SS]`；可选 `难度：Vn` |
| Prompt 版本 | `PROMPT_VERSION`（如 `2026-02-1`）写入记录 |
| Token 上限 | light ≈ 4096；deep ≈ 8192 |

### 5.2 Prompt 约束（产品契约）

- 人设：专业抱石教练，犀利但不过度攻击。  
- 禁止双引号（降低解析干扰）。  
- 必须输出完整分析，禁止空白或仅「无法分析」。  
- 轻量模式：字数/时间戳条数上限。  
- 深度模式：覆盖重心、发力、踩脚抓握、改进练习等维度。

### 5.3 后处理

1. `parseAnalysis`：时间轴、评分、金句、难度。  
2. `parseStructuredReport`：维度 bullet、改进块。  
3. 空正文 → 明确失败，不写入空记录。

### 5.4 可靠性需求

| 场景 | 产品行为 |
|------|----------|
| RPM 过密 | 提示约 N 秒后重试；Job 可 `rate_limited` |
| 日配额耗尽 | 明确文案；避免无限假重试 |
| 后台卡死 | 超时检测 + 有限次自动重试 |
| 用户取消 | Abort；文案「已取消」 |

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 单次分析体验目标 1～3 分钟（依赖视频长度与 Gemini 排队） |

| 安全 | API Key 仅服务端；密码 bcrypt；Session HttpOnly Cookie |
| 隐私 | 分析历史默认本机；免责声明：非医疗/保护建议 |
| 可维护 | Prompt 独立模块；Job 状态机集中在 `process-analysis-job` |
| 兼容 | 现代 Chromium / Safari；IndexedDB 可用 |

## 7. 技术约束与依赖

### 7.1 栈

- Next.js 16 App Router · React 19 · TypeScript · Tailwind 4  
- Gemini `@google/generative-ai`  
- Vercel Blob · `@vercel/functions` waitUntil  
- 可选：`@vercel/postgres` / Neon · jose JWT · bcryptjs  
- 前端：IndexedDB、html2canvas、jsPDF  

### 7.2 环境变量

| 变量 | 必需 | 用途 |
|------|------|------|
| `GEMINI_API_KEY` | 是 | 分析 |
| `GEMINI_MODEL` | 否 | 模型覆盖 |
| `BLOB_READ_WRITE_TOKEN` | 生产异步建议 | Job / 视频暂存 |
| `POSTGRES_URL` 或 `DATABASE_URL` | 注册功能 | 用户表 |
| `AUTH_SECRET` | 注册功能 | ≥16 字符会话签名 |
| `NEXT_PUBLIC_SITE_URL` | SEO 建议 | sitemap / OG |

### 7.3 关键模块索引

| 能力 | 路径 |
|------|------|
| Prompt | `lib/analyze-prompt.ts` |
| Gemini | `lib/gemini-analyze.ts` · `gemini-phases.ts` · `gemini-retry.ts` |
| Job | `lib/process-analysis-job.ts` · `analysis-jobs.ts` |
| 解析 | `lib/parse-analysis.ts` · `parse-structured-report.ts` |
| API | `app/api/analyze/route.ts` · `status/[jobId]` |

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 国内打不开 Vercel | 作品集不可达 | GitHub + 演示视频为主入口 |
| Gemini 免费额度 | 高峰失败 | 文案 + 重试；后续付费或换模型 |
| 模型输出不稳定 | 解析失败 / 空白 | 格式契约 + 空响应检测 + 版本化 Prompt |
| IndexedDB 仅本机 | 换设备丢历史 | 路线图云同步；简历中主动说明 |
| 简历被当成「调个 API」 | 低估工程量 | 用 DESIGN/PRD 强调流水线与可靠性 |
